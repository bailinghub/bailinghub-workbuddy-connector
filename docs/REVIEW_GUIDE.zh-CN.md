# 百灵中枢 WorkBuddy 连接器 0.1.2 重审说明

**当前状态：审核候选，尚未在 WorkBuddy 连接器市场上架。** 本文说明用户价值、候选版本变化和验收前提，不代表平台已通过审核或 Windows 实机验收已完成。

## 普通用户为什么需要它

商城运营人员可以在 WorkBuddy 中直接提出「查看最近 7 天订单，按状态整理」或「找出库存低于 10 件的商品」等请求，减少在后台查找入口与整理信息的步骤。对于已明确授权的低风险商品操作，例如修改测试商品的展示排序，连接器按业务系统声明执行；需要审批时，向用户报告进度，审批完成后恢复原调用。

工具由业务系统声明，权限由当前账号与业务规则决定。上述场景不表示候选包自带商城、演示数据或商品工具，也不表示已自动支持多个系统。没有已接入的业务能力时，应提示缺少前提或能力，不生成模拟成功结果。

## 测试前提

1. 使用满足候选清单要求的 WorkBuddy，确保其连接器环境可用 Node `>=20.15.0` 与 npm，且能够访问 npm 仓库；托管 Node 22 符合该范围。清单中的 WorkBuddy `5.0.0` 是协议下限，不代表已完成该版本实机验收。正式上传审核前，候选 ZIP 引用的 `bailinghub-workbuddy-connector@0.1.2` 必须已在 npm 公开可解析。
2. 开发者准备启用 Agent Auth v1 与 Agent Client Runtime v1 的百灵中枢部署、公开 Client App、允许的 workspace 和业务系统授权页。
3. 开发者提供公开 `hubUrl`、`clientAppId`、`workspace`；测试人员设置本地 `connectionName`。这些字段并不是 Client Token 或其他凭据。
4. 业务系统提供已授权的测试账号、订单查询能力、可恢复的低风险商品操作与测试数据。审批验收另外需要相应规则和审批人。

公开候选包不提供私有环境地址、账号或凭据。没有业务环境时，可以验收安装、版本检查与连接表单；真实授权、查询、写入和审批恢复属于尚未验证项。

## 建议验收顺序

### 1. Windows 安装与启动

- 从 WorkBuddy 审核入口安装 0.1.2 候选包，确认安装前的 Node/npm 版本诊断成功，Node 满足 `>=20.15.0`，npm 安装步骤正常退出，连接器版本检查结果为 `0.1.2`。
- 点击连接，确认本机配置页可以打开并正确显示中文，无需在聊天中复制密码或 Token。
- 完成授权后，确认连接状态可识别，MCP 能正常启动并提供五个固定工具。
- 如果失败，记录 WorkBuddy 版本、Windows 版本、失败阶段、退出码和脱敏日志；区分运行时获取、npm 安装、授权和 MCP 启动问题。敏感参数与完整授权回调地址不进入公开材料。

这些步骤是验收要求，不是已完成结果。非 Windows 环境的自动化检查不能替代 Windows WorkBuddy 实机安装证据。

### 2. 首次授权

填写四项公开连接信息后，应跳转到业务系统自己的授权页。测试人员在该页登录并选择允许的账号或门店；连接器不接收 Agent 自报身份。连接信息缺失或授权过期时，应明确引导补充公开参数或重新连接，不虚构可用业务环境。

### 3. 查询与低风险操作

先查询约定日期范围内的测试订单，核对结果与业务后台一致。再查询指定商品，确认目标明确后，使用业务系统实际声明的低风险操作修改测试字段，并核对后台结果。若未声明相应工具，应报告当前连接不具备该能力，不用其他接口代替。

### 4. 审批与未知结果恢复

对声明需要审批的测试操作，确认连接器报告等待审批并结束当前可见轮次，未重复提交。审批人通过业务流程处理后，由用户在新的可见轮次要求检查结果。连接器应恢复原 `invocation_id`，保留其原 run、连接与业务身份，而不是在新 run 内重发商品修改。

对于执行中或结果未知的调用，采用相同恢复边界，不在同一轮持续轮询。仅在返回状态确认执行成功后报告成功。结束一个可见 run 不等于待处理业务操作已完成。

### 5. 数据与会话边界

本机恢复文件只保留必要的标识、Schema、状态与时间，不保存用户消息、业务返回正文或凭据。可见输入、能力调用和最终答复会发往用户所选百灵中枢部署，其保存策略由该部署管理方决定；WorkBuddy 与模型服务另按各自设置处理会话。当前适配器按可见用户轮次隔离百灵中枢会话，不承诺自动归档完整 WorkBuddy 聊天。
